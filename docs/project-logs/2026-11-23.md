## 1. Current Firewall Architecture

The current security path is:

```text
                           Internet
                              |
                          GNS3 NAT
                              |
                          FortiGate
                              |
                             R2
                           /    \
                         R1------R3
                         |        |
                pfSense-Internal pfSense-Guest
                         |        |
                IT / Finance / HR Guest
```

The three firewall roles are intentionally separated:

| Firewall | Responsibility |
|---|---|
| FortiGate | Perimeter security and Internet egress control |
| pfSense-Internal | IT, Finance, and HR gateways and segmentation |
| pfSense-Guest | Guest gateway and isolation |

## 2. Client Gateway Migration to pfSense

The earlier router-on-a-stick design was retired.

R1 no longer owns:

```text
10.10.10.1
10.10.40.1
10.10.50.1
```

Those addresses are now owned by pfSense-Internal:

```text
IT       -> 10.10.10.1/24
Finance  -> 10.10.40.1/24
HR       -> 10.10.50.1/24
```

The Guest gateway is now owned by pfSense-Guest:

```text
Guest -> 10.10.20.1/24
```

R1 reaches the employee networks through the pfSense-Internal transit address:

```text
10.10.252.2
```

R3 reaches the Guest network through:

```text
10.10.253.2
```

The static protected-network routes are selectively redistributed into OSPF so the rest of the routed core can still learn them.

## 7. FortiGate Perimeter Policy

FortiGate sits between R2 and the GNS3 NAT node.

Current relevant interfaces:

```text
port1 -> DHCP from GNS3 NAT
port2 -> 10.10.254.1/30 toward R2
```

The internal address object is:

```text
INTERNAL-NETWORKS = 10.10.0.0/16
```

The active firewall policy is:

```text
Name:        Internal-to-Internet
Source:      INTERNAL-NETWORKS
From:        port2
To:          port1
Destination: all
Services:    HTTPS, DNS, NTP, PING
Action:      ACCEPT
NAT:         enabled
Logging:     enabled
```

Traffic that does not match an explicit FortiGate allow policy falls through to FortiGate's implicit deny behavior.

FortiGate also has a return route:

```text
10.10.0.0/16 -> via 10.10.254.2 -> port2
```

## 11. Important Troubleshooting Lessons

### Follow the Entire Traffic Path

A timeout at the destination does not necessarily mean the destination device is blocking the traffic.

For example:

```text
webterm-IT
   |
pfSense-Internal
   |
R1 / routed core
   |
destination firewall
```

Both pfSense-Guest and FortiGate management initially required checking the upstream pfSense-Internal policy.

### Specific Exceptions Must Precede Broad Blocks

The IT policy contains a broad private-network block.

Management exceptions for destinations such as:

```text
10.10.253.2
10.10.254.1
```

must appear above that block.

### Firewall Management and Transit Policy Are Different

A FortiGate transit firewall policy controls traffic moving through the firewall.

Administrative access to the FortiGate itself is also controlled by interface `allowaccess` settings.

Both parts of the path matter.

### Console Access Is an Important Recovery Tool

The pfSense console was used during a temporary GUI lockout.

The FortiGate serial console was used to confirm that FortiOS had booted normally during the filesystem-check reboot.
