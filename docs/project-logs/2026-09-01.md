## 1. GNS3 Smart App / Publisher Verification Issue

GNS3 suddenly stopped launching because Windows reported that it could not verify the publisher and confirm that the application was safe to run.

### Investigation

The installed executable was checked at:

```text
C:\Program Files\GNS3\gns3.exe
```

The executable did not show an embedded digital signature.

A fresh GNS3 2.2.61 installer was downloaded and checked before installation.

The installer showed a valid digital signature from:

```text
SolarWinds Worldwide, LLC
```

Windows reported:

```text
This digital signature is OK.
```

### Resolution

Before reinstalling, the following were backed up:

- GNS3 project files
- `%APPDATA%\GNS3`
- GNS3 VM location/settings
- Imported appliance/image files where applicable

GNS3 Desktop was then reinstalled using the verified installer.

After reinstalling:

- GNS3 launched successfully.
- The existing project opened successfully.
- The GNS3 VM connected normally.
- Routers, switches, clients, DHCP01, NAT, and existing links were intact.
- The newly installed `gns3.exe` still did not show an embedded digital signature.

The working conclusion is that the unsigned installed executable is part of the current package behavior, while the installer itself is signed and verified.

## 12. Key Lessons

### VLANs Separate Layer 2, Not Automatically Layer 3

Devices in different VLANs cannot communicate directly at Layer 2.

However, because R1 and R3 currently route between their VLAN subinterfaces, clients in different VLANs can still communicate at Layer 3.

Firewall or ACL-style policy is required to control which VLANs may communicate, which I will implement in the next session

### Same VLAN Across Multiple Switches

Switch1 and Switch3 extend VLANs 10, 40, and 50 over an 802.1Q trunk.

Devices in the same VLAN on the two switches remain in the same Layer 2 broadcast domain and can communicate without traversing R1.

### OSPF Passive Interfaces

A passive OSPF interface still advertises its connected network but does not send OSPF Hello packets or form neighbor adjacencies on that interface.

This is appropriate for:

- client VLAN subinterfaces
- the DHCP01 server-facing network

### Centralized Services and Redundancy

The failover test demonstrated that routing redundancy protects more than client-to-client traffic.

The alternate R1-R2-R3 path also preserved:

- DHCP
- DNS
- Internet access
