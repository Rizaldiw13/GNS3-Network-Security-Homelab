## Static Routing Lab

*Date: August 22, 2026*

Today I built the first working routed topology for the GNS3 homelab.

### Topology

The initial topology consists of two VPCS hosts and three VyOS routers:

PC1 --- R1 --- R2 --- R3 --- PC2

The lab uses `10.10.0.0/16` as the overall private address space. I divided the topology into four Layer 3 networks using VLSM.

### Addressing

- PC1 LAN: `10.10.10.0/24`
- R1-R2 transit: `10.10.100.0/30`
- R2-R3 transit: `10.10.100.4/30`
- PC2 LAN: `10.10.20.0/24`

Router-to-router links use `/30` networks because each point-to-point link only requires two usable IP addresses.

### Interface Configuration

PC1:
- IP: `10.10.10.10/24`
- Default gateway: `10.10.10.1`

R1:
- eth0: `10.10.10.1/24`
- eth1: `10.10.100.1/30`

R2:
- eth0: `10.10.100.2/30`
- eth1: `10.10.100.5/30`

R3:
- eth0: `10.10.100.6/30`
- eth1: `10.10.20.1/24`

PC2:
- IP: `10.10.20.10/24`
- Default gateway: `10.10.20.1`

### Initial Connectivity Testing

Before configuring static routes, I tested every directly connected network.

Successful tests included:

PC1 -> R1
R1 -> R2
R2 -> R3
PC2 -> R3

All directly connected interfaces were operational and showed an up/up state in VyOS.

I then attempted to ping PC2 (`10.10.20.10`) from PC1.

The ping failed with:
`Destination network unreachable`

This was expected because R1 only knew its directly connected networks and did not yet have a route to `10.10.20.0/24`.

### Static Routing

I configured static routes so each router knew how to reach the remote LANs.

R1:

`10.10.20.0/24 via 10.10.100.2`

R2:

`10.10.10.0/24 via 10.10.100.1`

`10.10.20.0/24 via 10.10.100.6`

R3:

`10.10.10.0/24 via 10.10.100.5`

After configuring the routes, PC1 and PC2 were able to successfully ping each other.

### Troubleshooting

While configuring R3, I accidentally added the following static route:

`10.10.10.0/24 via 10.10.20.1`

This was incorrect because `10.10.20.1` is R3's own eth1 address rather than a neighboring router.

This resulted in R3 showing two next hops for `10.10.10.0/24`.

I removed the incorrect next hop and kept:

`10.10.10.0/24 via 10.10.100.5`

where `10.10.100.5` is R2's interface connected to R3.

### End-to-End Verification

PC1 successfully pinged PC2:

`10.10.10.10 -> 10.10.20.10`

PC2 also successfully pinged PC1:

`10.10.20.10 -> 10.10.10.10`

Traceroute confirmed the expected path.

PC1 -> PC2:

PC1
-> R1 (`10.10.10.1`)
-> R2 (`10.10.100.2`)
-> R3 (`10.10.100.6`)
-> PC2 (`10.10.20.10`)

PC2 -> PC1:

PC2
-> R3 (`10.10.20.1`)
-> R2 (`10.10.100.5`)
-> R1 (`10.10.100.1`)
-> PC1 (`10.10.10.10`)

This confirms that IP addressing, subnetting, routing, and end-to-end connectivity are all functioning correctly.
